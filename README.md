# CanFilter G4 — USB-CAN адаптер на 3 канала для SocketCAN

Прошивка для платы [CanFilter на STM32G474](https://github.com/Sergey1560/canfilter_g4). Плата подключается к компьютеру с Linux по USB, и в системе появляются три CAN-интерфейса (`can0`, `can1`, `can2`). Работают с ними стандартными средствами SocketCAN: `ip link`, `candump`, `cansend` и т. д.

Прошивка совместима с протоколом candleLight. Плата определяется как `1d50:606f`, и её подхватывает драйвер `gs_usb`, который входит в ядро Linux. Ставить дополнительные драйверы не нужно.

## Возможности

- 3 независимых канала CAN 2.0 и CAN FD.
- Скорость задаётся с хоста, тактовая частота FDCAN 80 МГц.
  - CAN FD: в фазе данных до 5 Мбит/с, это предел трансиверов TJA1051T/3.
  - На высоких скоростях фазы данных включается компенсация задержки трансивера (TDC).
- Режимы `listen-only`, `loopback` (внутренняя петля), `one-shot`.
- Аппаратные метки времени, 1 мкс.
- В хост передаются:
  - состояния контроллера (error warning, error passive, bus-off) и счётчики ошибок;
  - ошибки протокола, если включён `berr-reporting`.
- Автоматическое восстановление после bus-off через 100 мс.
- Индикация состояния каждого канала RGB-светодиодом.
- Поиск платы светодиодом: `ethtool -p canN`.
- Обновление прошивки по USB через `dfu-util` без программатора.

## Аппаратная часть

Схема и печатная плата лежат в проекте KiCad [CanFilter на STM32G474](https://github.com/Sergey1560/canfilter_g4).

| Канал | Интерфейс Linux | TX | RX | Silent (S) | Примечание |
|---|---|---|---|---|---|
| CAN1 | `dev_port` 0 | PB9 | PB8 | PC13 | питание VIO трансивера от PB7; PB8 — это ещё и BOOT0 |
| CAN2 | `dev_port` 1 | PB13 | PB12 | PB14 | |
| CAN3 | `dev_port` 2 | PA15 | PB3 | PB4 | |

- USB Full Speed: PA11/PA12, тактирование от HSI48 с подстройкой CRS по SOF.
- Кварц 8 МГц, ядро работает на 160 МГц.
- Три светодиода WS2812 в одной цепочке на PB6.
- Терминаторы 120 Ом включаются перемычками на плате.

Линукс нумерует `canX` в порядке обнаружения. Номер канала на плате в свежих ядрах доступен в атрибуте `dev_port`:

```bash
cat /sys/class/net/can0/dev_port
```

## Использование

```bash
# Классический CAN, 500 кбит/с
sudo ip link set can0 up type can bitrate 500000
candump can0
cansend can0 123#DEADBEEF

# CAN FD: 500 кбит/с в арбитраже, 2 Мбит/с в фазе данных
sudo ip link set can1 up type can bitrate 500000 dbitrate 2000000 fd on
cansend can1 123##1112233445566778899AABBCC

# Проверка без шины (внутренняя петля)
sudo ip link set can2 up type can bitrate 500000 loopback on

# Состояние канала и счётчики ошибок
ip -details -statistics link show can0

# Найти плату: светодиод канала мигает жёлтым
ethtool -p can0 5
```

Изменить настройки можно только у опущенного интерфейса: `sudo ip link set canN down`.

## Индикация

У каждого канала свой светодиод. По умолчанию слева направо идут CAN1, CAN2, CAN3. Соответствие задаёт таблица `led_map` в [Src/led.c](Src/led.c).

| Цвет | Значение |
|---|---|
| Синий, мигает 1 Гц (все три) | нет связи с USB-хостом: кабель не подключён, хост не опознал плату или USB в suspend |
| Синий, горит постоянно | USB подключён, интерфейс опущен |
| Зелёный | интерфейс поднят, шина в порядке (error active) |
| Жёлтый | error warning или error passive: на шине ошибки |
| Красный | bus-off; через 100 мс начинается восстановление |
| Короткое гашение | принят или отправлен кадр; при плотном трафике светодиод мерцает |
| Жёлтый, мигает 2 Гц | `ethtool -p canN`, поиск платы |
| Фиолетовый (все три) | работает системный загрузчик, идёт обновление прошивки |

## Сборка

```bash
git clone --recurse-submodules <url репозитория>
cd CanFilter_socketcan
git submodule update --init

cmake -B build
cmake --build build
```

Путь к тулчейну задан переменной `GCC_TC_PATH` в [CMakeLists.txt](CMakeLists.txt). Поменяйте его под свою систему.

Результаты сборки лежат в `build/`:

| Файл | Назначение |
|---|---|
| `canfilet_socketcan.elf` | для отладчика |
| `canfilet_socketcan.bin` | образ для записи во флеш с адреса `0x08000000` |
| `canfilet_socketcan.dfu` | тот же `.bin` с DFU-суффиксом (CRC файла) для `dfu-util` |

## Прошивка

### Обновление по USB (на плате уже стоит эта прошивка)

Чтобы `dfu-util` работал без `sudo`, один раз установите правила udev:

```bash
sudo cp udev/99-canfilter.rules /etc/udev/rules.d/
sudo udevadm control --reload
```

Обновление:

```bash
cmake --build build --target dfu
```

То же вручную:

```bash
dfu-util -d 1d50:606f,0483:df11 -a 0 -s 0x08000000:leave -D build/canfilet_socketcan.dfu
```

Что при этом происходит:
1. `dfu-util` отправляет прошивке команду DFU_DETACH.
2. Плата отключается от USB, светодиоды становятся фиолетовыми, и плата перезагружается в системный загрузчик STM32. Он появляется как USB DFU-устройство `0483:df11`.
3. `dfu-util` стирает и записывает флеш, затем запускает новую прошивку.

В конце `dfu-util` может написать `Error during download get_status`. Это нормально. Загрузчик ST запускает прошивку сразу по запросу leave и уже не отвечает на последний запрос статуса.

### Первая прошивка

Есть два варианта:

- **Через системный загрузчик.** Удерживайте кнопку BOOT0 и подключите USB, плата появится как `0483:df11`. Затем:
  ```bash
  dfu-util -d 0483:df11 -a 0 -s 0x08000000:leave -D build/canfilet_socketcan.dfu
  ```
- **Через SWD** любым программатором (J-Link, ST-Link): запишите `canfilet_socketcan.bin` с адреса `0x08000000` или загрузите `.elf` в отладчик. Для Segger Ozone в репозитории есть проект `ozone.jdebug`.

### Отладочный вывод

Лог выводится через SEGGER RTT, канал 0. Его можно смотреть в J-Link RTT Viewer или в Ozone.

## Устройство прошивки

Операционной системы нет: главный цикл и прерывания.

```
FDCANx IRQ ─► кольцевой буфер (128 кадров) ─► bulk IN  ─► Linux gs_usb
Linux gs_usb ─► bulk OUT ─► слоты канала (12 шт.) ─► TX FIFO FDCAN ─► шина
                                    ▲                       │
                                    └── эхо ◄── TX event FIFO
```

| Файл | Назначение |
|---|---|
| [Src/main.c](Src/main.c) | инициализация и главный цикл |
| [Src/gs_usb.c](Src/gs_usb.c) | протокол gs_usb: вендорские запросы, обмен кадрами, эхо, error-кадры |
| [Src/usb.c](Src/usb.c) | USB-дескрипторы, тактирование USB, VID:PID в [Src/usb.h](Src/usb.h) |
| [Src/led.c](Src/led.c) | индикация на WS2812 |
| [Lib/Mylib/can.c](Lib/Mylib/can.c) | драйвер FDCAN: тайминги, режимы, приём, передача, состояния, bus-off |
| [Lib/Mylib/bootloader.c](Lib/Mylib/bootloader.c) | переход в системный загрузчик по DFU_DETACH |
| [Lib/Mylib/rcc.c](Lib/Mylib/rcc.c) | тактирование: HSE 8 МГц → PLL, ядро 160 МГц, FDCAN 80 МГц |
| [Lib/Mylib/systime.c](Lib/Mylib/systime.c) | TIM2 — счётчик микросекунд для меток времени, SysTick — миллисекунды |
| `Lib/tinyusb` | USB-стек [TinyUSB](https://github.com/hathach/tinyusb) 0.21.0, git submodule |

Конфигурация USB:
- интерфейс 0 — vendor-интерфейс gs_usb с bulk-эндпоинтами `0x81` (IN) и `0x02` (OUT);
- интерфейс 1 — DFU Runtime для `dfu-util`.

## Ограничения

- **Пропускная способность.** Драйвер `gs_usb` передаёт по одному кадру за USB-транзакцию, а USB Full Speed ограничивает суммарный поток примерно десятком тысяч кадров в секунду на все три канала. Это оценка, а не замер. Обычной загрузки автомобильных шин хватает с запасом, но три шины на 1 Мбит/с под 100 % нагрузкой не пройдут.
- **Аппаратные фильтры не используются.** Контроллер принимает все кадры, фильтровать нужно в Linux (фильтры сокетов, `candump can0,123:7FF`).
- **Кадр, не отправленный в режиме `one-shot`,** тоже возвращается хосту как эхо, и `ip -s link` посчитает его отправленным. Протокол gs_usb не умеет сообщать хосту, что кадр не отправлен.
- **VID:PID `1d50:606f` общий со всеми устройствами candleLight.** Отличить плату можно по строкам Manufacturer/Product (`CanFilter G4 gs_usb`) и серийному номеру. Серийный номер равен UID микроконтроллера.
- **Сброс из отладчика в ревизии v0.1.** Плата может стартовать в системном загрузчике вместо прошивки. Причина: конденсатор питания трансивера CAN1 медленно разряжается через R106, трансивер остаётся запитанным и выставляет высокий уровень на CAN1_RX, то есть на BOOT0 (PB8). Помогает замена R106 на резистор меньшего номинала, например 1 кОм.
